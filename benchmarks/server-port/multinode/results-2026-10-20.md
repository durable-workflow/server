# Multi-node results, 2026-10-20

The full schedule passed on MySQL 8.4, MariaDB 10.11, PostgreSQL 17 and
SQLite. Every one of the 1,080 offered workflows completed exactly once, with
its original output and an ordered history, while server nodes were killed
and restarted and a worker was paused past its lease. The database audits
found no duplicate committed outcome and no duplicate history sequence. No
native node panicked.

| Database | Workflows verified | Node kills | Worker pauses | Duplicate outcomes | Stale workflow completions refused | Worker exits |
| --- | --- | --- | --- | --- | --- | --- |
| MySQL 8.4 | 270 of 270 | 26 | 3 | 0 | 1 | 2 |
| MariaDB 10.11 | 270 of 270 | 25 | 3 | 0 | 1 | 3 |
| PostgreSQL 17 | 270 of 270 | 26 | 3 | 0 | 0 | 2 |
| SQLite | 270 of 270 | 27 | 3 | 0 | 0 | 3 |

Each workflow's activity ran once. No activity completion was lost to a
killed node, so none waited for the five-minute activity lease.

## Identity

- Harness: `68d78be19` (MariaDB: `eeb510a3a`, which adds its profile), each
  run from a clean detached checkout.
- Native binary: an unoptimized dev-profile build of `rust-325-workflow-lease`
  `ce18934e1`, SHA-256
  `53d634e8fb7d96cab64d768e01d47db6e8c2f5a634cf0d6e67e6047b95ac03a9`. This
  checks correctness, not speed.
- Clients: the capacity bindings' locked PHP SDK 2.0.10. A later run used SDK 2.5.3 (below).
- Machine: one Intel i5-6500 host with 4 logical CPUs and no other workload.
- Raw node, balancer and worker logs were inspected and not kept. Each run's
  summary is in `summary-<database>-2026-10-20.json`.

## Worker exits

Workers exited and were restarted 10 times in all:

- **Native refusal shape (8 exits, all by the paused worker).** After a pause,
  the worker sent requests for workflow tasks the server had given to the
  other worker. Native refused the late lease renewals (`task_not_leased`) and
  completions (`conflicting_completion`) with only a reason and the task
  fence. Published PHP refuses the same requests with its ownership guard's
  fields: the task status, and whether the run is closed. A current worker
  reads those fields to drop a lost claim.
  [#548](https://github.com/durable-workflow/server/pull/548) makes native
  return PHP's bodies, with a parity fixture.
- **SDK 2.0.10 poll (2 exits).** A poll got HAProxy's HTML 503 while a killed
  node was still marked up. SDK 2.0.10 treats that body as invalid JSON and
  exits. The SDK has retried polls on that failure since
  [sdk-php#69](https://github.com/durable-workflow/sdk-php/issues/69).

Current SDKs still exit when the same proxy failure hits a request for a
task that is already claimed:
[sdk-php#197](https://github.com/durable-workflow/sdk-php/issues/197).

## Confirmation with the ownership guard

The same schedule ran again with native built from
[#548](https://github.com/durable-workflow/server/pull/548) (`f43e6fae2`,
unoptimized dev profile, SHA-256
`4c19c325cbd175d58d0b2710bb0450241f3760730514788eedf5185bab312e8f`) and the
harness at `1a8add148` (MariaDB: `eeb510a3a`). Summaries are in
`summary-guard-<database>-2026-10-20.json`.

| Database | Workflows verified | Node kills | Duplicate outcomes | Worker exits |
| --- | --- | --- | --- | --- |
| MySQL 8.4 | 270 of 270 | 27 | 0 | 4 |
| MariaDB 10.11 | 270 of 270 | 25 | 0 | 3 |
| PostgreSQL 17 | 270 of 270 | 27 | 0 | 3 |
| SQLite | 270 of 270 | 27 | 0 | 2 |

No native node panicked. Every late request from the paused worker was now
refused with PHP's ownership guard body. Eleven exits followed a late lease
renewal after the run had closed, refused with `run_closed` and
`can_continue: false`, the body published PHP returns. SDK 2.0.10 has no
lost-claim handling (the SDK added it in 2.2.6), so it exits on that refusal
from either server. The twelfth exit was the SDK 2.0.10 poll case above.

## Current SDK

The schedule ran a third time with the published PHP SDK 2.5.3 installed in
place of the bindings' locked 2.0.10, and native from #548 as above. Summaries
are in `summary-sdk253-<database>-2026-10-20.json`.

| Database | Workflows verified | Node kills | Duplicate outcomes | Worker exits |
| --- | --- | --- | --- | --- |
| MySQL 8.4 | 270 of 270 | 25 | 0 | 0 |
| MariaDB 10.11 | 270 of 270 | 26 | 0 | 0 |
| PostgreSQL 17 | 270 of 270 | 24 | 0 | 0 |
| SQLite | 270 of 270 | 25 | 0 | 0 |

With a current SDK, the workers stayed up through every node kill and pause.
Across the four runs the paused worker got 7 lost-claim refusals from native
(`409` on a late lease renewal or completion) and dropped each claim without
exiting.

An earlier PostgreSQL run with the same SDK had one worker exit. A node was
killed while answering that worker's lease renewal, and the balancer returned
502, which the SDK does not retry while a task is claimed
([sdk-php#197](https://github.com/durable-workflow/sdk-php/issues/197)). The
exited worker still held its lease. Native recovered the expired lease as PHP
does, recording `RepairRequested`, and the workflow completed once. The
workload then accepted only the happy-path events and flagged that history.
It now accepts and counts the recovery, and the PostgreSQL row above is the
rerun.

## Concurrent bootstrap

All three nodes of each run start together against the empty database. In a
later smoke run on MySQL, one node exited with `unsupported_rust_schema`: it
started while another node was between creating the native marker table and
recording its marker. MySQL and MariaDB commit DDL on their own, so that state
is visible. The correction lets the node wait for the bootstrap lock, and its
kill qualification covers the window.

## Earlier attempt

The first full MySQL run had no balancer retry and no worker restarts. Both
workers exited on HAProxy 503 pages while killed nodes were still marked up,
and window 2 completed nothing. That run measured the clients rather than the
server. It led to the connect-failure retry and the restart policy in the
current harness.
