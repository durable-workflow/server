# Repeated matched observations, October 20

Two alternating PHP/native pairs on one dedicated experiment host, after #516
landed on main. They repeat the [morning pair](observations-2026-10-20.md)
with the same workload, artifacts, limits and commands. These are development
observations on one host and one database family, not a release claim.

## Conditions

- **Source.** Server main `8957ba27a` (#516 merged), native tree `55aec4d8`.
  The optimized binary was built with `cargo build --release --locked --bin
  durable-workflow-server`, SHA-256 `edc283f1…6e2cc`. The PHP references,
  PHP SDK, MySQL and Redis artifacts are the profile's, unchanged.
- **Host.** A fresh Vultr `vhp-4c-8gb-amd` VM: 4 vCPU AMD EPYC-Rome, 7.7 GiB,
  Ubuntu 24.04.5 with kernel 6.8, Docker 29.1.3 and Compose 2.40.3, no swap.
  No other workload ran. It ran from 13:15 to 15:48 UTC, was deleted at the
  end and its deletion was verified, at about $0.20.
- **Procedure.** A native smoke check, then PHP, native, PHP and native full
  runs in that order. Each run uses its own Compose project and fresh
  database. Each run is the morning procedure: warmup, three 120 s windows at
  0.25, 0.5 and 1 workflow/s, the 0.25/s windows repeated after as a drift
  check, and mixed idle polls. The four runs' summaries are in
  `summary-repeated-{php,native}-{1,2}-2026-10-20.json`.

All four runs finished with status 0. Every window's workflows verified, with
nothing pending. No container restarted or was OOM-killed.

PHP still does not sustain 1/s. Its in-window completions at 1/s fell from
93–96 this morning to 62–69 here, and its 1/s median latency grew from 15–18 s
to 45–56 s. Its CPU per workflow also rose about a quarter on this host, as the
next table shows. Native completed all 120 in both pairs here and this
morning. The two PHP runs agree with each other, and so do the two native runs.
So the change is between hosts, not drift within this one.

## What this shows and what it does not

On this profile, native meets or beats PHP on throughput, CPU, memory and idle
long-poll cost in every window of two repeated pairs. The before and after
windows show no drift within any run.

It does not show the result on PostgreSQL or SQLite, on other machine types,
across nodes, or under the CPU-heavy deadline profile. The host-to-host change
in PHP's capacity also says one host is not enough for a release claim. The
driver records host load and swap but not CPU steal. Sampling steal in
`host-state.tsv` is the next change to the driver.
