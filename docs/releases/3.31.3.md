# Durable Workflow Server 3.31.3 (native)

This release keeps the 3.30.0 database schema on every backend. Existing
deployments on 3.30.0 through 3.31.2 can upgrade without a schema migration.

## Polling and activity recovery

- A later held workflow or activity poll checks storage admission again after
  releasing its read connection. A storage-pressure change during the wait
  produces the typed retryable 503 with the original poll identity.
  [Server #1392](https://github.com/durable-workflow/server/pull/1392)
- Activity retries recover the latest acknowledged checkpoint for the same
  activity execution even when the run has 1,000 or more newer heartbeats
  from sibling activity executions. Liveness-only heartbeats leave that checkpoint available. The
  restored details and acknowledgement timestamp come from the original
  checkpoint. [Server #1396](https://github.com/durable-workflow/server/pull/1396)

## Namespace and repair configuration

- `DW_HISTORY_RETENTION_DAYS` sets the retention period for the first
  `default` namespace and new bounded namespaces that omit a period. Native
  Server accepts 1–365 days and defaults to 30. Each existing namespace keeps
  its stored policy. Use the namespace retention plan to preview and apply
  corrections to previously seeded values.
- Workflow-level message stream list, detail and append requests now work in
  named namespaces. Requests for a workflow owned by another namespace are
  refused.
- `DW_V2_TASK_REPAIR_LOOP_THROTTLE_SECONDS` controls the interval for native
  repair passes that request throttling. The interval applies within a process
  across namespaces and queues. Its default is five seconds and zero disables
  it. [Server #1400](https://github.com/durable-workflow/server/pull/1400)
