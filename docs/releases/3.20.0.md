# Durable Workflow Server 3.20.0 (native)

Native Server reports ready workflow and activity tasks whose exact type is
missing from the active worker registrations on their queue. Queue diagnostics
and operator metrics give counts by queue, task kind, and type. They also
count tasks on queues without an active poller and jobs whose stored type
cannot be classified.

The workflow list API includes the affected queue and type on runs with an
unsupported ready task. Waterline 2.21.0 shows that information on the run
list. Check the configured queue and type name, including case, and register
a worker that supports the type. The finding clears once the Server sees a
matching active registration or the task leaves the ready backlog.

See [task queue diagnostics](../server-reference.md#task-queues) and
[Server #535](https://github.com/durable-workflow/server/issues/535) for details.

## Upgrade from 3.19.0

The database schema and worker protocol are unchanged. Replace the 3.19.0
image with 3.20.0 using your normal rollout procedure. The published Compose
file defaults to 3.20.0. Roll back by pinning the 3.19.0 image. Upgrades from
3.17.x still need the [stopped-node schema upgrade](3.18.0.md#upgrade-from-317x).
