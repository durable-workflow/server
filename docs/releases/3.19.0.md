# Durable Workflow Server 3.19.0 (native)

Native Server records HTTP request duration in the
`dw_http_request_duration_seconds` histogram. Scrape each replica with an
instance-wide credential to see durations by matched route template, HTTP
status, and request kind. Worker polls have their own kind and include time
spent waiting for work. The metric starts at the Server router and ends when
the response is ready. Tenant-scoped scrapes continue to expose their own
namespace metrics.

Set `DW_HTTP_ACCESS_LOG=true` to write a JSON timing record to stderr for
each completed response. The log includes the route template, method, response
status, request kind, and elapsed time. URLs, request bodies, and identifiers
stay out of these records. Access logs are off by default.

See [Request timing](../server-reference.md#request-timing) for a Prometheus
query and guidance on comparing Server and SDK measurements.
[Server #668](https://github.com/durable-workflow/server/issues/668)

## Upgrade from 3.18.0

The database schemas and worker protocol are unchanged. Replace the
3.18.0 image with 3.19.0 using your normal rollout procedure. You can roll
back to 3.18.0 with the previous image. The published Compose file defaults
to 3.19.0. Upgrades from 3.17.x still need the
[stopped-node schema upgrade](3.18.0.md#upgrade-from-317x).
