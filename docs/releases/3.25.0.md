# Durable Workflow Server 3.25.0 (native)

Workflows can opt in to start their next run on the promoted build. Server
selects the eligible build for the successor's exact namespace, queue and
workflow type when it closes the predecessor. Both run histories record the
choice. Plain continue-as-new keeps the predecessor's pin. If no build is
eligible, Server leaves the current run open and the worker reports the failure
through the workflow task's normal retry path.
If the run closes before the retry, run detail still shows the refusal and the
cancelled task without a scheduled retry time.

A worker that offers targeted continuation and receives confirmation at
registration uses protocol 1.21 for the continuation and its refusal report.
Other worker endpoints keep the 1.20 contract. Upgrade the eligible workers
before enabling targeted continuation in application code.

## Upgrade from 3.24.0

The database schema is unchanged. For Docker Compose, replace the published
Compose file and start the stack with the new image. Server verifies the
existing schema at startup. For an earlier schema, follow the
[stopped-node upgrade](3.22.0.md#upgrade-from-3210).
