# Durable Workflow Server 3.17.1 (native)

Native Server now honors `wait_new_event=1` on the run history endpoint
([Server #1257](https://github.com/durable-workflow/server/issues/1257)).
When no event follows `next_page_token`, the request waits for a committed
event or the configured `DW_WORKER_POLL_TIMEOUT`. An existing page returns
immediately. A timeout returns an empty page. Omitting the flag or using `0`
keeps the immediate read.

The server releases its database connection between checks. A local commit
wakes readers of the selected run, and two nodes sharing a database can
observe each other's commits through a one-second fallback check.

Upgrade from 3.17.0 by replacing the image. The schema and protocol versions
are unchanged. The published Compose default selects `3.17.1`.
