# Durable Workflow Server 3.18.0 (native)

Native Server reports repeated workflow task lease loss in run descriptions,
observations and lists, and in operator metrics ([Server #1255](https://github.com/durable-workflow/server/issues/1255)).
The diagnostic includes the task ID, consecutive losses, threshold and last
loss time. It clears when the task completes or the run closes. The default
threshold is three losses and can be changed with
`DW_V2_WORKFLOW_TASK_LOST_LEASE_ATTENTION_THRESHOLD`.

When cluster info advertises `task_attention_workflow_list`, `GET /api/workflows`
accepts `task_attention=true` and `task_attention=false`. The Server applies the
filter before pagination and echoes the applied value in `task_attention_filter`.
PHP SDK 3.24.0 can pass the filter through and verify the Server applied it.

Responses eligible for compression now include `Vary: Accept-Encoding` so a
cache can keep compressed and uncompressed responses distinct
([Server #1265](https://github.com/durable-workflow/server/issues/1265)).

## Upgrade from 3.17.x

Stop all native Server nodes, take a verified database backup, and run the new
image's `schema-upgrade` command before starting the nodes on 3.18.0. Use the
[documented stopped-node upgrade procedure](../../rust/README.md#native-schema-upgrades).

| Database | 3.17.x schema | 3.18.0 schema |
| --- | ---: | ---: |
| SQLite | 17 | 18 |
| PostgreSQL | 18 | 19 |
| MySQL | 19 | 20 |
| MariaDB | 18 | 19 |

The upgrade adds lease-loss fields for open workflow tasks. Existing tasks begin
with zero recorded losses. To roll back after the schema change, restore the
pre-upgrade backup and start the previous image. The worker protocol remains
1.20. The published Compose default selects `3.18.0`.
