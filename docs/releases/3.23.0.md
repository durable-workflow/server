# Durable Workflow Server 3.23.0 (native)

External workers can supply `workflow_id` when they start a child workflow.
Server assigns that application ID to the child instance in its parent's
namespace. The child keeps the instance ID across retry and continue-as-new.
The server still generates each run ID and the parent-issued call ID.

The `child_workflow_explicit_id` capability advertises support. The worker
command accepts up to 128 characters drawn from ASCII letters, digits, and
`._:-`. A collision refuses the parent task completion with
`child_workflow_id_unavailable` and keeps its lease and history intact.

## Upgrade from 3.22.2

The database schema and worker protocol version are unchanged. For Docker
Compose, replace the published Compose file and start the stack with the new
image. Server verifies the existing schema during startup. An earlier schema
still requires the [stopped-node upgrade](3.22.0.md#upgrade-from-3210).

When a deployment runs multiple task completion producers, upgrade all of
them before enabling explicit child IDs in worker code.
