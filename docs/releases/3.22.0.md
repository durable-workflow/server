# Durable Workflow Server 3.22.0 (native)

When a child in a flat parallel `all()` group completes while siblings remain,
Server can advance the parent's waiting summary from a verified checkpoint and
the new child event. The final child completion still checks the whole group
before resuming the parent. Failures continue to reach the parent immediately.
[Server #1295](https://github.com/durable-workflow/server/issues/1295)

Worker registration now validates and retains the parallel group policy
descriptor in the worker's registration snapshot. Existing parallel group
semantics continue to apply. Explicit policy support is tracked separately.
[Parallel group policies](https://github.com/durable-workflow/.github/issues/232)

## Upgrade from 3.21.0

Stop all native Server nodes and take a verified database backup. Run the
3.22.0 image's `schema-upgrade` command before starting the nodes on the new
image. The upgrade adds the child-summary checkpoint table and its guards.
Existing waiting summaries use full verification until they have a checkpoint.
[Stopped-node schema upgrade](../../rust/README.md#native-schema-upgrades)

| Database | 3.21.0 schema | 3.22.0 schema |
| --- | ---: | ---: |
| SQLite | 18 | 19 |
| PostgreSQL | 19 | 20 |
| MySQL | 20 | 21 |
| MariaDB | 19 | 20 |

On a binlogged MySQL or MariaDB server, if the upgrade reports
`native_child_checkpoint_trigger_privilege_required`, keep the nodes stopped
while your database administrator applies the staged DDL. Then rerun
`schema-upgrade` with the application credentials.
[Staged checkpoint DDL](../../rust/README.md#child-summary-checkpoints-on-mysql-and-mariadb)

To roll back after the schema upgrade, restore the pre-upgrade backup before
starting the previous image. The published Compose file defaults to 3.22.0.
