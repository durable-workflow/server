# Durable Workflow Server 3.27.0 (native)

A compatible worker can evaluate a timed condition after the timer fires
using signal and successful update effects received before the original
`TimerFired` event. The first prefix that satisfies the predicate determines
the recorded result. In a selection with a child workflow or supported
child group, Server compares that prefix with the child's original success
or failure event. Existing recorded outcomes continue to replay as recorded.

## Upgrade from 3.26.0

The database schema is unchanged. For Docker Compose, replace the published
Compose file and start the stack with the new image. Server verifies the
existing schema at startup. For an earlier schema, follow the
[stopped-node upgrade](3.22.0.md#upgrade-from-3210).

Ordered wait authoring is off by default. Upgrade all Server processes that
can reach the database, including failover and maintenance processes, and
install compatible SDK workers before setting
`DW_ORDERED_CONDITION_WAIT_AUTHORING=1`. For Compose, set it in the environment
used to launch Compose and recreate the Server service. See the
[rollout and rollback runbook](../../rust/README.md#rolling-out-durable-input-ordering-for-timed-waits).
