# Durable Workflow Server 3.21.0 (native)

Run diagnostics identify ready workflow and activity tasks that are waiting
for worker capacity. The `eligible_worker_slots_busy` finding appears when
every active worker eligible for the task has a fresh report of zero free
slots for that kind of work. It includes the queue, task kind, task type,
and eligible worker count.

Open the run diagnostics in Waterline 2.22 or run
`dw debug workflow <workflow-id>` to see the finding. Check the matching
workers and their concurrency. The finding clears when a matching worker
reports a free slot or the task leaves the ready queue.

[Server #579](https://github.com/durable-workflow/server/issues/579)

## Upgrade from 3.20.0

The database schema and worker protocol are unchanged. Replace the 3.20.0
image with 3.21.0 using your normal rollout procedure. The published Compose
file defaults to 3.21.0. Roll back by pinning the 3.20.0 image. Upgrades from
3.17.x still need the [stopped-node schema upgrade](3.18.0.md#upgrade-from-317x).
