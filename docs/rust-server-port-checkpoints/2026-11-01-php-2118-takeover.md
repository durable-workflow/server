# November 1, takeover of published Server 2.11.8

- **Before.** Native refused every published 2.11.8 database as
  `upgrade_source_catalog_unqualified`. Server 2.11.8 (Core 2.15.12; image
  index `sha256:3848d5d5cd1b23bd2881e3fdecea64cc44b72e6fb812e577c2db6d0872d065dd`)
  was published today with #911's committed payload deletion (#789).
- **Layouts.** Core 2.15.12 adds no migration over 2.15.7. 2.11.8's only
  change is Server's `runtime_external_payload_deletions` table. Two layouts
  record it:
  - `php-2.11.8` descends from `php-2.11.3`;
  - `php-2.11.8-from-2.9.7` descends from `php-2.11.3-from-2.9.7`.
- **Captured from real databases.** The published images bootstrapped fresh
  2.11.7 and 2.11.8 databases, and 2.9.7 databases migrated by each, on
  SQLite, MySQL 8.0, MariaDB 10.11 (through the `mysql` connection) and
  PostgreSQL 17. Each path gave the same delta from its parent. Native's
  `upgrade-inspect` then named all eight real 2.11.8 databases by their
  layout, and the 2.11.7 ones still `php-2.11.3`.
- **Recipe** (details in [the layout README](../../rust/upgrade/php-2.11.8/README.md)).
  - Each pending deletion moves to native's `dw_external_payload_deletions`
    with its id, namespace, object, saved policy, attempt count, recorded
    failure and times (`external_payload_deletions_copied`). Native retries
    it as PHP does, so none is dropped. Takeover deletes no object.
  - PHP's table is then dropped.
  - Inspection reports `external_payload_deletion_inspection`. Takeover
    refuses before any change
    (`upgrade_source_external_payload_deletions_unsupported`) while a
    pending deletion's saved policy is one native cannot execute (empty,
    disabled, another driver, or a non-`file://` root) or it records a
    failure PHP does not write.
  - MySQL and MariaDB run this as journal step 11, which repeats safely.
- **Tests.**
  - SQLite: `takeover_carries_php_2118_pending_deletions_over` covers both
    layouts; `takeover_refuses_a_php_2118_deletion_native_could_never_finish`
    checks every refusal (another driver, `[]`, `{}`, `enabled: false`, an
    unknown failure) leaves the file byte-identical.
  - PostgreSQL, MySQL and MariaDB:
    `qualification_takeover_carries_php_2118_pending_deletions_over`.
  - CI: a `php2118` upgrade cohort backs up, takes over and resumes a
    published 2.11.8 source on SQLite, PostgreSQL and MySQL/MariaDB.
- **Not covered.** A Laravel `mariadb` connection source was not captured
  separately; its known difference (the backup-hold owner) is unchanged, and
  the new table has no column of that kind.
