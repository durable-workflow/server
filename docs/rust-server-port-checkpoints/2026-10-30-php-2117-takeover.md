# October 30, takeover of published Server 2.11.7

- **Question.** The release candidate must upgrade in place from the last
  PHP release. Native records layouts up to 2.11.3. Published since then:
  2.11.4, 2.11.5, 2.11.6 (not a reference, #861) and 2.11.7.
- **Finding.** 2.11.4, 2.11.5 and 2.11.7 add no migration. A fresh SQLite
  bootstrap of each has the same `sqlite_master` definitions as a fresh
  2.11.3 database (392 objects), and the same last migration
  (`2026_10_26_000100_create_workflow_service_call_dispatches_table`). So
  their databases have the `php-2.11.3` layout, or `php-2.11.3-from-2.9.7`
  when 2.9.x created them, and the 2.11.3 recipe applies unchanged. No
  native code changes.
- **Evidence.** Locally, the existing upgrade cohort
  (`upgrade-source-profile.sh sqlite`) ran against published 2.11.7, image
  `sha256:be7c2288…`. Native fingerprinted the source as `php-2.11.3`, took
  it over (`taken_over`), and resumed the published PHP originals
  (`native_resumes_published_php_originals_after_takeover`: pass).
- **CI.** A `php2117` cohort, beside `php2113`, now backs up, takes over and
  resumes a published 2.11.7 source in the SQLite, PostgreSQL and
  MySQL/MariaDB cohort parts.
