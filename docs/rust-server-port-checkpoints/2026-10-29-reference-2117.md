# October 29, the parity reference moves to published 2.11.7

- **Before.** The Shared Server fixtures compared native and embedded
  against published Server 2.11.5 (Core 2.15.1).
- **Reference.** Published Server 2.11.7, Core 2.15.7, as General published
  it and Security accepted it (#861):
  - source `f55f90e54a213872f1c164a1b22c082d859c18aa`;
  - index `sha256:96e3e7de8c58f31bfb1ef4d5bddddc2678f4684f5cb3505e6e9ddc6fa3f7f625`;
  - linux/amd64 `sha256:be7c2288ff935396262d743590530b204fac11b76582e56a525cc81a8da840d3`;
  - linux/arm64 `sha256:7dbc3db050fec05ea5cd10e07ac8399ecf3e285d593bca32979a2320f02a104f`.

  `tests/Fixtures/ServerParityBaselines/php-2.11.7.json` records it. The
  SDK, CLI, Waterline and sample-app pins are unchanged.
- **Why not 2.11.6.** A local survey of published 2.11.6 found that a
  repeated bridge-adapter update answered `500` (#861). 2.11.7 carries the
  fix (#862).
- **Survey.** Every fixture in `tests/Fixtures/ServerParity` was recorded
  locally against the 2.11.7 amd64 image, SQLite, maintenance loop running,
  except `service-calls` (local SQLite lock pressure) and
  `visibility-current-runs` (it needs the published CLI artifact CI
  provides). Results:
  - 72 of 74 pass unchanged, `bridge-adapters` among them: 2.11.7 gives the
    intended answers at all three of its published-defect steps;
  - `schedule-catalog` fails locally the same way on 2.11.5;
  - `waterline-import` changes as expected (below).
- **Expectation change.** Server #812 (#770) counts a v1 projection's
  history bytes as Core's `HistoryBudget::sizeOfEvent` does: the event
  type's bytes plus its payload as `json_encode` with
  `JSON_UNESCAPED_SLASHES | JSON_UNESCAPED_UNICODE`. That is the unit
  `DW_V2_LIMIT_HISTORY_TRANSACTION_BYTES` limits everywhere else.
  `waterline-import` records five `history_size_bytes` values:

  | Export | 2.11.5 | 2.11.7 |
  | --- | --- | --- |
  | project | 5431 | 4713 |
  | running | 2683 | 2445 |
  | failed | 5425 | 4707 |
  | offsets | 6242 | 5336 |
  | bare | 1856 | 1668 |

  No other value in that fixture changed.
- **Native.** The prepared meter change (`e0ed32a6`, held since October 27
  for this move) counts each event the same way, for the byte limit and
  for the stored summary.
- **Local checks before the pull request.**
  - `waterline-import` was recorded against a fresh 2.11.7 harness and
    against a native image built from this branch. Both pass, and
    `compare` accepts the pair. The 2.11.7 recording equals the stored
    contract observation (with the five new sizes) exactly.
  - The Rust library and integration suites pass (634 and 359).
  - The node unit suite passes, except the PHP image-context test,
    which fails the same way on a clean `main` checkout here because of
    local ignored state.
- **Not changed here.** The `bridge-adapters` contract still accepts the
  published-defect answers of 2.11.1 to 2.11.5. 2.11.7 no longer gives
  them, so a later change can make that contract exact.
