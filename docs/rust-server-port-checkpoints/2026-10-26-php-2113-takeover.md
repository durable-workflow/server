# October 26, takeover of published Server 2.11.3

- **Before.** Native refused every published 2.11.3 database as
  `upgrade_source_catalog_unqualified`. Server 2.11.3 (Core 2.14.2) was
  published today, image index
  `sha256:923a8924ecad13485562d7af30dc87d7fd6d9d7d4758ec8113bac0766fa8603e`.
- **Layouts name their parent.** `SOURCE_LAYOUTS` was a chain: each delta
  applied to the layout before it. 2.11.3 has to apply to both 2.11.1
  variants, so each layout now names the layout its delta applies to.
  `layout_lineage` gives the path from the frozen layout, and
  `every_recorded_layout_descends_from_an_earlier_one` checks the order.
  - `php-2.11.3` descends from fresh `php-2.11.1`.
  - `php-2.11.3-from-2.9.7` descends from `php-2.11.1-from-2.9.7`.
- **Captured from real databases.** The published images bootstrapped and
  migrated SQLite, PostgreSQL 17, MySQL 8.0 and MariaDB 10.11 databases along
  five paths:
  - fresh 2.11.3;
  - 2.11.1 then 2.11.3;
  - 2.8.0 then 2.11.3;
  - 2.9.7 then 2.11.3;
  - 2.9.7, 2.11.1, then 2.11.3.

  Each path gave the same delta from its parent on every backend. The first
  three end at `php-2.11.3` and the last two at `php-2.11.3-from-2.9.7`. The
  native binary then inspected, fingerprinted and took over all five real
  SQLite databases.
- **Recipe** (details in [the layout README](../../rust/upgrade/php-2.11.3/README.md)).
  - Each active session's recorded holder incarnation is copied to
    `dw_worker_session_holders`. Earlier releases record none, so takeover
    derives the holder from the current registration. A 2.11.3 session that
    PHP already orphaned stays orphaned.
  - `message_full` is counted (`full_failure_messages_removed`) and dropped.
  - The idempotency digest and its index are dropped.
  - Completed dispatches are counted (`service_call_dispatches_removed`) and
    the outbox is dropped. A scheduled or claimed dispatch refuses takeover
    before any change (`upgrade_source_service_call_dispatches_pending`), and
    inspection reports `service_call_dispatch_inspection`.
  - `reclaim_at` and its index are dropped.
  - MySQL and MariaDB run this as journal step 10. Each part checks what is
    left to do, so a resumed step repeats safely.
- **Tests.**
  - SQLite: `takeover_converts_php_2113_databases` covers both layouts, with
    a held session, a replaced holder, a full failure message, a completed
    dispatch and an idempotency digest.
    `takeover_refuses_a_php_2113_dispatch_still_pending` checks that a
    pending dispatch refuses and leaves the file byte-identical.
  - PostgreSQL, MySQL and MariaDB:
    `qualification_takeover_converts_php_2113_and_native_opens_it`.
  - MySQL and MariaDB: the step-kill test also kills a 2.11.3 takeover
    after step 9 and resumes it.
  - CI: a `php2113` upgrade cohort backs up, takes over and resumes a
    published 2.11.3 source on SQLite, PostgreSQL and MySQL.
- **Not yet native.** The parity reference is still 2.11.1. Core 2.14 also
  changed behavior that native does not follow yet:
  - full failure-message storage on write;
  - service-call scheduling through the outbox;
  - the idempotency scope of target namespace, names and key, with
    `service_call_idempotency_scope_conflict`.

  These belong to the parity move to 2.11.3.
