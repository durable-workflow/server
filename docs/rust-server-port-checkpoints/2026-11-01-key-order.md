# November 1, key order in plain input and search attribute errors

- **Before.** Native's plain JSON input reached the Avro writer through
  `memos::from_json`, whose maps are `BTreeMap`s:
  - a nested object was encoded with sorted keys, so its blob differed from
    PHP's while the decoded values were equal;
  - a nested object with keys 0 to n-1 in any order read as a list, so
    `{"1": "a", "0": "b"}` became `["b", "a"]`;
  - before #906 (`serde_json` without `preserve_order`), an object input's
    values and several search attribute errors also came out in sorted key
    order.
- **Contract** (published 2.11.7, Workflow 2.15.7).
  `PayloadEnvelopeResolver::resolve` takes a plain input's values in
  document order (`array_values`) and serializes them. `Avro::toDatum`
  encodes a PHP list (`array_is_list`) as an Avro array and any other array
  as a map in document order. Its keys must be strings, and `json_decode`
  turns a canonical integer string into an integer key, so an integer-keyed
  object that is not a list fails with `invalid_map_key`:
  - on a start, Core's exception reaches the controller, which answers
    `422 validation_failed` with the message under `workflow_type`, and no
    run is created;
  - on a signal, it answers `500 control_plane_internal_error`
    (`operation_failed`, `indeterminate`).

  `SearchAttributeValueValidator` loops over the attributes in request
  order, so several errors on a start (`search_attributes`) or on one
  upsert command (`commands.N.attributes`) are reported in that order.
- **Native.** `plain_input::ordered` converts plain input to an
  `OrderedValue` in document order with `Avro::toDatum`'s rules, and the
  ordered Avro writer encodes it (`queries::encode_ordered_arguments`). Every
  plain input path uses it: start, bridge start, standalone activity
  start, signal, update, query and message stream append. A refusal on a
  non-bridge start is PHP's validation failure under `workflow_type`; the
  other paths keep `422 invalid_workflow_arguments` rather than PHP's 500.
  Search attribute errors already followed request order after #906.
- **Ordered writer.** `ValueCodec::encode_ordered_value` used Apache's datum
  writer over the binding schema and then read its own blob back. Plain
  input can nest 511 levels (`deep-json-bodies`), and those two steps
  overflowed even a 64 MiB stack there. The writer now emits the protocol
  Value's Avro binary layout directly, one small frame per level, and does
  not read the blob back. A 511-level value encodes in a 2 MiB stack. A unit
  test checks it byte for byte against Apache's binding writer, and the
  existing test against PHP's published bytes still passes. Query routing,
  the other caller, writes the same bytes as before.
- **Fixture.** `key-order`, recorded against published 2.11.7 on SQLite,
  in a fresh namespace without registered attributes. The probe sends each
  body as the fixture's JSON text, so key order and integer keys survive:
  - a nested map, whose stored input blob is PHP's exact bytes (`zeta`
    before `alpha`, `yak` before `bee`);
  - `{"1": "a", "0": "b"}` and `{"second": "b", "first": "a"}` as the whole
    input, stored as `["a", "b"]` and `["b", "a"]`; native before #906 gave
    the second as `["a", "b"]`;
  - `[{"1": "a", "0": "b"}]` and `[{"1": "a"}]`, refused with the 422;
  - a signal's nested map, stored in document order;
  - three invalid search attributes, `Zz`, `9bad`, `Aa`, on a start and on
    an upsert command, reported in that order; native before #906 gave
    `9bad`, `Aa`, `Zz`.

  The fixture passes against published 2.11.7 (recorded twice) and against
  native on SQLite. The native recording ran before the direct writer
  replaced the binding writer; the two write identical bytes.
- **Tests.** `plain_input.rs` unit test; `wire_order.rs`
  `the_direct_writer_matches_apache_s_binding_writer`; `key_order.rs` execution tests
  (PHP's exact blobs, the refusal, the signal blob and the error order);
  `ServerParityKeyOrderContractTest.mjs`, which rejects sorted maps, sorted
  object values, out-of-order integer keys read as a list and sorted errors.
