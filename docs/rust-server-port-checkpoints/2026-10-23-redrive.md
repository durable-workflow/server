# October 23, run redrive

- **What is served.** `POST /api/workflows/{id}/runs/{run}/redrive` now
  behaves as published Server 2.11.1's `DefaultWorkflowControlPlane::redrive`
  and `FailedRunRedrivePlan`:
  - A run that failed right after an activity failed continues in a new
    run. Its history is `StartAccepted`, `WorkflowStarted` and an
    `ActivityCompleted` for each completed step before the failed one.
    Each reused event names the source run.
  - `WorkflowStarted` carries the source run, `resume_step_sequence`,
    `recovery_kind: redrive`, the source deadlines, and the source's
    definition fingerprint. The new run gets a workflow task, so the worker
    replays the reused steps and schedules only the failed activity again.
  - A repeated `request_id` answers 200 with the run it already created.
  - Each refusal PHP makes is made here with PHP's reason and status:
    - `run_not_failed`;
    - a failure without an activity boundary, `unrecorded_failure_boundary`;
    - `source_run_not_current`;
    - memos or search attributes on the source,
      `unsupported_visibility_metadata`;
    - a child link or external arguments,
      `unsupported_source_link_or_payload`;
    - a passed execution deadline, `execution_deadline_elapsed`;
    - a missing or changed definition fingerprint,
      `workflow_definition_unavailable_or_changed`;
    - a reused `request_id`, `request_id_already_used`.
  - `request_id` longer than 191 characters is refused with Laravel's
    message.
  - Describe on the redriven run shows the source run as
    `continued_from_run_id`.
- **How it was checked.** A probe ran the same scenario against native and
  the published 2.11.1 image on SQLite:
  - a failed run with a recorded boundary;
  - each refusal;
  - the redrive, and its repeat;
  - the resumed activity;
  - completion.

  Statuses, reasons, the replayed history and the resumed step matched.
  The integration test `redrive_resumes_a_failed_run_at_its_failed_activity_like_php`
  passes on SQLite, PostgreSQL and MySQL.
- **Remaining difference.** `POST /api/workflows/{id}/redrive` without a run
  is not a route on PHP. PHP answers its general 404; native answers its
  general 501 for an unknown API route. That fallback is server-wide, and is
  tracked with the other response shapes.
