# October 26, takeover of published 2.11.1 databases

- **Found by.** Native upgrade inspection of a database that the published
  Server 2.11.1 image bootstrapped answered `upgrade_source_catalog_unqualified`.
  Native recognized only the frozen, 2.8.0 and 2.9.7 layouts, so no
  installation on the current release could take over in place.
- **Layout.** Core 2.10.2 (in Server 2.11.1) adds a nullable
  `observability_context` column, Core's trace carrier, to `workflow_runs`,
  `workflow_commands` and `workflow_tasks`. Server's own migrations are
  unchanged from 2.9.7. The deltas were read from databases the published
  image bootstrapped on SQLite, PostgreSQL 17, MySQL 8.0 and MariaDB 10.11
  ([`rust/upgrade/php-2.11.1`](../../rust/upgrade/php-2.11.1/README.md)).
- **Two physical variants.** Core's migrations run in file order.
  - A fresh 2.11.1 database puts the task carrier before 2.9.7's
    `queue_delivery_reference`.
  - A database 2.9.7 created and 2.11.1 then migrated has the opposite
    order. It is recorded separately, read from real 2.9.7 databases that the
    2.11.1 image migrated
    ([`php-2.11.1-from-2.9.7`](../../rust/upgrade/php-2.11.1-from-2.9.7/README.md)).
  - Inspection names whichever matches. MariaDB through Laravel's `mariadb`
    connection adds `+mariadb-driver` to either.
- **Conversion.** As decided on
  [#325](https://github.com/durable-workflow/server/issues/325#issuecomment-6306545520),
  takeover counts the carried values, reports them as
  `observability_contexts_removed`, and drops the three columns. It also drops
  2.9.7's delivery reference and adopts PHP's worker incarnations, as for 2.9.7.
  MySQL and MariaDB take this as journal step 9, which counts every carrier
  before dropping any column, so an interrupted takeover repeats it safely.
- **Tests.**
  - `takeover_converts_php_2111_databases_and_drops_their_trace_carriers` on
    SQLite.
  - `qualification_takeover_converts_php_2111_and_native_opens_it` on
    PostgreSQL 17, MySQL 8.0 and MariaDB 10.11.
  - Each builds both variants from the frozen layout and seeds a run and a task
    that carry a trace context. It then checks the layout name, the count of 2,
    that the columns are gone, and that native opens the database.
  - Every other takeover qualification test still passes on the three
    databases.
- **Real databases.** Native prepared, fingerprinted and took over a SQLite
  database bootstrapped by the published 2.11.1 image (`php-2.11.1`) and one
  bootstrapped by 2.9.7 and migrated by 2.11.1 (`php-2.11.1-from-2.9.7`).
- **CI.** Each database job's upgrade cohorts gain a labeled run against the
  published 2.11.1 image, as for 2.9.7.
- **Search attribute definitions.** Takeover no longer refuses a source
  holding custom search attribute definitions. Native reads PHP's rows as
  they are, to list them, type `upsert_search_attributes` values and filter
  visibility. `takeover_keeps_php_search_attribute_definitions_that_native_then_lists`
  checks that native lists a 2.11.1 database's definitions after takeover.
- **Worker sessions.** Takeover no longer refuses a source holding worker
  sessions.
  - Native records which registration incarnation holds each session and
    orphans a session whose holder is no longer the worker's current
    registration.
  - So takeover records, for each active PHP session, the lease owner's
    current incarnation (adopted from PHP's own) as its holder, and reports
    `session_holders_recorded`. MySQL and MariaDB do it in journal step 3,
    with the incarnations.
  - `takeover_keeps_php_worker_sessions_held_by_their_current_registration`
    checks that native still reads such a session as active. Without the
    holder, native reads it as orphaned with `worker_registration_replaced`.
  - The 2.11.1 qualification tests check the recorded holder on PostgreSQL,
    MySQL and MariaDB.
- **Service calls.** Takeover no longer refuses a source holding Nexus
  service calls.
  - Native serves them from PHP's own rows. It keeps each call's deadline in
    `dw_service_call_deadlines`, so takeover copies 2.8.0+'s
    `call_deadline_at` there before dropping the column, and reports
    `service_call_deadlines_copied`. MySQL and MariaDB copy in journal step 6,
    and only what is not copied yet.
  - PHP's shared admission counters live in its cache and do not carry over.
  - `takeover_keeps_php_service_calls_and_their_deadlines` checks the copied
    deadline and that the repair pass then times the due call out. The 2.11.1
    qualification tests check the copied deadline on PostgreSQL, MySQL and
    MariaDB.
- **Repair pass.** The pass now times out due service calls as PHP's
  `TaskWatchdog::runPass` does:
  - up to 25 admitted open calls past their deadline, earliest first, within
    the pass's runs and instance;
  - a requested connection or queue matches the caller's or linked run
    exactly; a call with neither run matches any scope.

  Before, it reported the three service-call counters as zeros.
  `the_repair_pass_times_out_calls_past_their_deadline` covers it.
- **Still refused.** Takeover still refuses a source holding rows native
  cannot carry over yet: runtime credentials, message streams, update
  validation tasks and external payloads.
